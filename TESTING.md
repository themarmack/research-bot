# Testing

The toolkit is tested in three layers. The rule that keeps it cheap: **push
everything you can into the free deterministic layers; keep the AI layer thin
and run it sparingly.**

| Layer | What it checks | AI? | API key? | When |
|-------|----------------|-----|----------|------|
| **0 — unit** | Python logic: `render_and_send.py`, the 3 cadence engines, plist builders, the email recipient parser | No | No | every commit / PR (free) |
| **1 — structural lint** | data-file schemas + cross-refs (pytest) and `evolve run checks` (Tier 0) | No | No | every commit / PR (free) |
| **2 — AI evals** | skill trigger accuracy (Tier 1) + behavioral output (Tier 2), via `evolve` | Yes | **No** — rides the `claude` CLI login | locally / scheduled; CI gates committed results only |

## Do I need an Anthropic API key?

**No, for running the evals.** `evolve` shells out to your already-logged-in
`claude` CLI for triggers, evals, *and* the LLM judge — it uses your Claude Code
subscription. A key is *optional* and only adds pre-run cost **estimates**
(measured cost still comes back from the CLI). CI needs no key at all.

## Commands

```sh
make setup    # venv + prod & dev deps (one-time)
make test     # Layers 0+1 — pytest, deterministic, free
make lint     # evolve Tier-0 static checks
make gate     # evolve report --check against COMMITTED results (no agents)
make check    # test + lint + gate = the full CI gate (no agents, no key)

make evals    # LOCAL ONLY — runs trigger suites via the claude CLI (uses tokens)
make report   # regenerate EVALUATION.md from committed results
```

## Token discipline

- **CI runs Layers 0+1 + `evolve report --check` only** — zero agent tokens, no
  secrets. It gates the AI tier by reading *committed* `results.yaml`, never by
  running agents on shared runners.
- **AI runs are local/scheduled**, on a single cheap model (Haiku), `max_turns:
  8`, `baseline: false` (all pinned in `.evolve.yaml`). `make evals` uses
  `--modified --failed` so only changed/failed cases re-run. Use `evolve run
  evals --count-only` to estimate before spending.
- Trigger accuracy is **model-specific**: Haiku is the frugal default; add your
  real model only in periodic full sweeps.

## Authoring a new eval suite

Create `evals/<skill-name>/` (matching the skill dir under `skills/`, which is a
symlink to `.claude/skills/`):

- `triggers.yaml` — Tier 1. Each case: `query` + `should_trigger`. Include
  **negatives that should route to a sibling skill** — they test that a
  description isn't over-broad. See `evals/email-sender/triggers.yaml`.
- `evals.yaml` — Tier 2 (optional). Each case: `id`, `prompt`, and at least one
  `assertions`/`expectations` entry. Deterministic assertions (`file_exists`,
  `regex`, `command`, `tool_call`) cost zero LLM tokens; each `expectations`
  line is one judge call — use them sparingly. **Caveat:** skills that write to
  the Obsidian vault have side effects outside the eval workspace; those need
  fixture-based, workspace-scoped assertions (deferred — no template yet).
- `results.json` — generated by `evolve run …` (evolve's default results
  format); **commit it** so CI can gate on it without running agents.

## Deterministic tests

Live in `tests/`. They import the repo's hyphenated, non-package scripts by file
path via `tests/_util.py:load_module`. The highest-value one is
`tests/test_cadence.py`: the three cadence engines (`schedule-sync`,
`_catch_up_helper`, `schedule-status`) must agree on every cadence shape, or
catch-up/status silently drift.
